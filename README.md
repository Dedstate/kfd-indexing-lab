# Ускорь индексацию

Подборка доступных товаров по рекомендациям с учётом исключений и повторений.

[Полное задание](docs/TASK.md). Решены обязательная и необязательная части.

## Начало работы

Нужен JDK 21 или новее. Запуск всех тестов из корня репозитория:

```bash
./gradlew clean build
```

Windows PowerShell:

```powershell
.\gradlew.bat clean build
```

Для запуска только тестов: `./gradlew test` (Windows: `.\gradlew.bat test`).

## Основное задание

### Решение

**Файл с реализацией `selectProducts`:**

[`src/main/kotlin/lab2/ProductSelection.kt`](src/main/kotlin/lab2/ProductSelection.kt).
Реализация использует [`IndexedProductCatalog`](src/main/kotlin/lab2/IndexedProductCatalog.kt).

**Как работает функция и почему выбран такой способ обработки данных?**

`selectProducts` строит индекс товаров `id -> Product` через `associateBy`, затем вызывает
`IndexedProductCatalog.select` без ограничения числа результатов. Для каждого запроса
формируется множество исключений через `toHashSet()`. Рекомендации просматриваются
последовательно, поиск товара и проверка исключения выполняются в среднем за O(1).
Поэтому не требуется линейный поиск по каталогу для каждой рекомендации.

**Как сохраняются порядок рекомендаций и уникальность товаров? Как обрабатываются исключённые, недоступные и неизвестные товары?**

Результат пополняется при первом *подходящем* появлении ID в `recommendedIds`, поэтому
приоритет рекомендаций сохраняется независимо от порядка каталога. Множество
`selectedIds` не позволяет повторно добавить выбранный товар. ID из `excludedIds`
пропускаются; отсутствующие в индексе и товары с `available = false` не добавляются.
Возвращаются исходные объекты `Product`; входные коллекции не изменяются.

### Сложность

Обозначения:

- `p` — число товаров в каталоге;
- `r` — число идентификаторов в рекомендациях;
- `e` — число идентификаторов в исключениях;
- `k` — число товаров в результате, `k <= min(p, r)`.

**Время выполнения:** ожидаемое `O(p + e + r)` — создание индекса `O(p)`,
множества исключений `O(e)` и однократный проход по рекомендациям `O(r)`.
Оценка предполагает среднее `O(1)` для операций хеш-таблиц (`HashMap`/`HashSet`);
при патологических коллизиях гарантии линейного времени нет.

**Дополнительная память:** `O(p + e + k)` — индекс `O(p)`, исключения `O(e)` и
множество выбранных ID `O(k)`. Память для самого списка результата — отдельно
`O(k)`; объекты `Product` не копируются.

## Необязательное продолжение

**Статус:** Выполнено.

### Организация решения

**Файлы с реализацией и пример вызова:**

- [`IndexedProductCatalog.kt`](src/main/kotlin/lab2/IndexedProductCatalog.kt) — индекс и запрос с `limit`;
- [`IndexedProductCatalogTest.kt`](src/test/kotlin/lab2/IndexedProductCatalogTest.kt) — тесты продолжения.

```kotlin
var catalog = IndexedProductCatalog(
    listOf(Product(1, "Keyboard", true), Product(2, "Mouse", true))
)
val result = catalog.select(
    recommendedIds = listOf(2L, 1L, 2L),
    excludedIds = emptyList(),
    limit = 1
) // [Product(2, "Mouse", true)]

// Загрузка другого каталога: создаём новый индекс.
catalog = IndexedProductCatalog(listOf(Product(3, "Monitor", true)))
```

**Что выполняется при загрузке каталога, а что — при каждом запросе? Как обеспечиваются независимость запросов и переход на новый каталог?**

При создании `IndexedProductCatalog` один раз строится неизменяемая для запросов
таблица `productsById`. Каждый `select` создаёт собственные множества `excluded`
и `selectedIds`, а также список результата. Состояние запросов не разделяется.
Для смены каталога создаётся новый экземпляр `IndexedProductCatalog`; он хранит
индекс нового каталога, исходный изменяемый список ему не требуется.

**Когда прекращается просмотр рекомендаций? От чего зависит число просмотренных элементов?**

При `limit = 0` рекомендации не просматриваются. При положительном `limit` цикл
прерывается сразу после добавления `limit`-го подходящего товара. Число
прочитанных рекомендаций `t <= r` зависит от расположения подходящих ID,
исключений, недоступности, неизвестных ID и повторений; если товаров не хватает,
просматриваются все `r` элементов.

### Сложность

`p` — число товаров в каталоге, `e` — длина исключений, `r` — длина
рекомендаций, `t <= r` — число реально просмотренных рекомендаций,
`k <= min(limit, p, t)` — длина результата (при положительном `limit`).

| Этап | Время | Дополнительная память |
| --- | --- | --- |
| Подготовка каталога | В среднем `O(p)` | `O(p)` для индекса |
| Один запрос (`limit > 0`) | В среднем `O(e + t)` | `O(e + k)` без результата |
| Один запрос (`limit = 0`) | `O(1)` | `O(1)` |

**Обоснование оценок и память для результата:**

При подготовке каждый товар один раз добавляется в хеш-индекс. Запрос обрабатывает
исключения и только фактически прочитанный префикс рекомендаций. В `selectedIds`
запоминаются лишь добавленные ID, а не все встретившиеся. Для списка результата
дополнительно требуется `O(k)` ссылок, без копирования объектов `Product`.
Оценки времени основаны на среднем `O(1)` для операций с хеш-таблицами.

### Проверка продолжения

| Что проверяется | Тесты |
| --- | --- |
| Нулевой лимит | `zeroLimitDoesNotReadRecommendations` |
| Досрочное заполнение результата | `stopsReadingRecommendationsOnceLimitIsReached` |
| Подходящих товаров меньше лимита | `returnsAllEligibleProductsWhenLimitIsGreaterThanTheirCount` |
| Несколько независимых запросов к одному каталогу | `usesRequestLocalExclusionsAndSelectionState` |
| Переход на новый каталог | `creatingIndexForNewCatalogUsesNewProductValues` |

**Как подтверждено досрочное завершение?**

В тесте `stopsReadingRecommendationsOnceLimitIsReached` передаются 7 рекомендаций
`[999, 1, 1, 2, 42, 2, 1]` и `limit = 1`; товар с ID `1` доступен, а `999`
неизвестен. Класс `CountingRecommendations` увеличивает `readCount` при каждом
вызове `get(index)`; после запроса `readCount == 2`, хотя список содержит
7 элементов. Учёт чтений не вмешивается в возвращаемый результат.
